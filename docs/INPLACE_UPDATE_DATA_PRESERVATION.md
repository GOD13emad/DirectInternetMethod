# Direct Internet Method — single installation and data-retaining upgrades

**Owner objective:** one installed version per host, in-place updates, no lost settings or custom profiles, no growing installer/snapshot caches and no unsafe automatic deletion. This document describes the candidate R401 change; it is not permission to run QA code on installed user devices before actual release acceptance.

## Authority and layout

- **Windows:** one Inno Setup AppId `{B5388E8B-9AF3-41F4-87E2-01C9601A36CB}`, one registered install directory, one native service. Updater must use the exact registered installation directory rather than installing beside an older version. Windows-managed code remains below `%LOCALAPPDATA%\Programs\DirectInternetMethod` and privileged services below `%ProgramFiles%\DirectInternetMethod\Privileged`. Mutable settings live separately below `%ProgramData%\DirectInternetMethod\UserConfig` and `%LOCALAPPDATA%\DirectInternetMethod`, and Direct engine network state remains under `%ProgramData%\DirectDnsDpiHarness`.
- **Linux:** one user installation at `~/.local/share/DirectInternetMethod`; root-owned backend `/usr/lib/directinternetmethod` is a separately authorized dependency. The user-level updater snapshots **only version-controlled program files** in one private pending transaction directory `~/.local/state/DirectInternetMethod/update-pending` and refuses a second transaction. On accepted commit, it removes that staging snapshot; on failure it attempts exact rollback, preserving unresolved snapshots instead of guessing or overwriting foreign data. There must be **no new timestamped backup directories**.
- User configuration is explicitly outside the managed-code set: `settings.json`, `strategy.txt`, `scope.txt`, `custom-hosts.txt`, `adult-enabled.txt`, `adult-hosts.txt`, `adult-hosts.meta.json`, Router Gateway user-modified providers, runtime logs and active network state. The installer computes and checks before/after hashes; when uncertain, it fails closed.
- Linux uninstaller must recover protected network state, finish protected backend removal, then remove **only exact SHA-owned executable files and known launchers**. It must never run `rm -rf` against the mixed code/user-data tree. User preferences can be reused by a later installation without manual import.

## Windows legacy uninstaller safety

Previous installed versions may carry dangerous `[UninstallDelete]` records from older installers (for example, recursively deleting `{app}\evidence`). Inno Setup appends previously recorded uninstall actions by default when upgrading the same AppId. For this safety migration the next installer uses `UninstallLogMode=overwrite` on the **same AppId and directory**, explicitly removing inherited recursive cleanup actions. It no longer deletes `{app}\evidence`, `{app}\bin` or the privileged directory recursively as an unowned container. This protects user data but may leave some historical untracked program files; these must be classified by ownership and SHA before removal. A second install directory or unregistered orphaned application copy is a **blocking conflict**, not an invitation to silently install side by side.

## Windows updater cache

The new updater uses a single known file `%ProgramData%\DirectInternetMethod\updates\DirectInternetMethod-update-stage.exe` plus one `.part`, and one `pending-update.json` identity record. It rejects occupied staging slots, confirms GitHub digest == public SHA256SUMS == download hash, then hands the existing registered installation directory to Inno. Successful upgrade finalization is owned by the **newly restarted Windows Service**, not by Inno Setup: Inno preserves `pending-update.json`, the new service asynchronously checks the exact installer SHA and removes only its known temporary installer once unlocked. If cleanup cannot complete, the pending record remains and further updates refuse duplicate staging; no false `done` is shown. Interrupted or failed install evidence is not silently erased. Older versioned updater installers are classified as historical caches and **not automatically deleted from active v1.5.1 devices** until the newer installed version and rollback gates pass.
